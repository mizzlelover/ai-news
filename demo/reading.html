给领域使用者的入口

你不必先知道该看谁，
才配拥有一套情报体系。

如果你刚进入一个行业、产业或细分领域，手上只有“我想了解数字文旅产业”这样的关键词，这已经足够成为第一步；如果你已经在领域里，手上有一些专业信源但总觉得覆盖不够广，也可以从同一个起点开始。私人情报所先帮你建立领域知识域，再让你决定下一步要深入什么。

一句话定位

私人情报所不是替你订一份 AI 日报，而是让你从一个领域关键词或一批已有信源开始，逐步建立自己的领域知识域、人物、专家、信源、知识引擎、日报与持续追踪系统。

两类使用者，同一个起点

第一类 · 最重要 刚进入一个领域的人

没有知识背景，不知道领域边界、权威专家和可信来源，甚至不知道该提出什么问题。先从一个领域名字开始，建立第一版知识域。

第二类 已经在领域里，但覆盖不够广的人

已有专业信源、专家或工作材料，但信息集中在熟悉圈层。以已有信源为种子，向外发现相邻参与者、早期信号和知识盲区。

两类人的共同目标，是构建想进入或已经身处其中的领域情报知识域：知道领域由什么组成，知道谁在持续产生信息，知道什么来源值得信任，也知道目前还不知道什么。日报、推送和知识引擎，是这个知识域建立之后的更新与交付工具。

网上很多工具要么围绕 AI 从业者追踪 AI，要么要求使用者先会配置工具、先写出专业问题。私人情报所把入口放回“领域知识域”，不是技术配置或一次性提问。已经能够独立配置信源、搭建日报并维护知识引擎的人，不是本项目的主要目标用户。

你只需要提供什么

我想了解/进入的领域是：数字文旅产业

可选补充：我现在和它的关系是准备进入、正在从业，或需要研究。

如果你已经在领域里，也可以补充：我已经在关注哪些专家、网站、项目或材料。

你不需要先学会爬虫、RSS、API、数据库、Prompt 工程或 GitHub Actions。那些是实现层的零件，不是使用门槛。

两类使用者，四个真实现场

第一类 · 从零进入 县域文旅项目负责人

先看政策、项目、客群、供应商、运营方和竞争格局，再决定要不要深入某类项目和落地路径。

第一类 · 从零进入 教育工作者或研究者

从职业教育、智能制造人才培养等领域名开始，连接政策、试点、论文、供应商、教师社区与学生反馈。

第二类 · 已在领域里 制造业与供应链负责人

已有设备、供应商或行业信源，但想补齐标准、材料、交付、客户采用和现场反馈，发现熟悉圈层之外的变化。

第二类 · 已在领域里 已有信源的行业人士

先用领域知识域校准自己的信息边界，再把某个判断转成第二层 Focused Watch，而不是把一次研究误当成长期情报系统。

从领域知识域到每日简报

01
一个领域关键词行业、产业、知识域、细分领域，甚至一个尚未整理的词都可以。
02
领域边界、词典与观察面先知道这个领域由什么组成，而不是立刻要求你写出完整提纲；已有信源的人也从这里查找盲区。
03
人物、机构、项目与资料找到正在定义、改变或最早感知这个领域变化的参与者。
04
不同角色的高质量信源官方原文负责确认，专家负责解释，前沿来源负责发现，一线记录负责观察落地。
05
知识域更新、覆盖审计与日报回看来源过去是否有效，显示还不知道的地方，最后才生成日报与推送。

一份好的简报长什么样

数字文旅产业 · 候选信号

今天发生了什么：周边两座目的地开始把研学客群从团队游转向周末小团。

为什么值得看：过去 14 天出现项目发布与课程调整两条独立运营方信号。

当前边界：这不是“市场已经验证”的结论，仍需补查运营数据、客单价和复购。

怎么开始

  1. 刚进入领域：回到领域入口，输入一个行业、产业或关键词；不需要先有背景或问题。
  2. 已经在领域里：输入领域名称，并带上已有的专家、网站、项目或材料，作为向外扩展的种子。
  3. 观察系统先展开领域地图、人物与机构、高质量信源和知识引擎，再从知识域里选择真正想深入的方向。
  4. 让知识域进入持续更新、日报和推送；如果需要工程协作，再进入工程页面，不必让技术学习成为第一道门槛。

核心方法论 V0.1

方法不是技术黑话，而是一条判断路径。

这套方法把“一个领域关键词或一批已有信源 → 领域知识域 → 可持续的信息生态”变成一条可复盘的工程流水线。领域知识域是核心，日报只是最后一种交付形态。

两类人，先做同一件事

刚进入领域的人，需要从零找到该知道什么、该看谁、该信谁；已经在领域里的人，需要从已有信源向外发现缺口。两条路径最后都汇入同一个领域知识域，之后才进入更新、日报、推送和具体问题追踪。

01
Domain Seed保存领域名称、别名和用户进入动机，允许只给一个词启动。
02
Domain Map + EIE把领域拆成边界、观察面和必须掌握的 Essential Information Elements。
03
Expert Attention Reconstruction从专家、来源、资料、组织和主题关系中重建专业注意力，而不是排粉丝榜。
04
Historical Replay在 point-in-time 截点上检验来源过去是否提前提供过有用信号。
05
Source Portfolio按角色、质量、成本和互补性组合来源，减少信息盲区。
06
Knowledge Engine + Coverage Audit记录已掌握、待确认和缺口，避免用网页数量伪造覆盖率。
07
Daily Brief + Focused Watch领域知识域成熟后，再叠加日报、推送和具体问题追踪。

两层工作模式

层级输入输出适用时机
domain_foundation一个领域名称或关键词；也可加已有信源边界、词典、参与者、专家、来源地图、知识引擎底图刚进入领域，或已经在领域里但希望拓宽覆盖
focused_watch领域底图 + 一个判断/问题PIR、细化 EIE、事件优先级、历史回放和专项推送已经知道要持续盯住哪条线

Source Role 不等于 Reliability

不同来源承担不同观察职责，可靠性则回答它能否被信任。官方源可能权威但慢，专家源可能解释好但覆盖窄，前沿传感器可能早但噪音高，广覆盖源能防漏但需要筛选。

official_primary原始发布与权威确认

政策、规则、公告和正式数据。

expert_interpreter解释机制与影响

研究者、行业专家和专业分析。

frontier_sensor发现尚未主流化的信号

前沿社区、现场记录和早期项目。

community观察使用与反馈

从业者讨论、用户反馈和一线经验。

三个必须可审计的机制

EAR重建注意力网络

每条边保存关系强度、主题相关性、证据置信度和观察时间，通过 Personalized PageRank 传播并做跨圈层校正。

Historical Replay严格 point-in-time

区分事实最早可获得时间与权威确认时间，只允许使用截止时已经可获得的观察。

Portfolio优化互补组合

综合角色、质量、成本、边际覆盖和 Bundle synergy，不把来源做成单一总榜。

Coverage Audit知道自己不知道什么

对每个 EIE 输出来源、覆盖比、缺口原因和历史证据状态，保留诚实的未知。

来源生命周期

discovered → candidate → approved → observing → validated → active
                    ├→ rejected             └→ watchlist → retired

进入 active 前至少需要来源角色、主题或 EIE 映射、获取路径、证据记录和历史回放结果。来源健康下降时进入 watchlist，不自动删除。

当前边界与下一步

  • 核心引擎保持离线、确定性和可测试，不把外部搜索、爬虫、LLM、数据库或调度器硬编码进去。
  • 选定一个公开资料丰富的领域，先从 Domain Seed 生成边界、词典和观察面。
  • 为每个观察面建立异质 Expert Seed、人物/机构和来源候选，并记录关系证据与时间。
  • 冻结历史 cutoff，比较普通热门列表与 EAR 的跨圈层来源及组合增益。

给工程协作者的入口

把领域地图变成可持续的情报引擎。

Domain Intelligence Bootstrap 是私人情报所的核心工程。它解决的不是“再抓一批新闻”，而是把来源、证据、覆盖缺口和领域日报排序纳入同一份可审计资产。

最小领域入口

from domain_intelligence.models import DomainProfile

profile = DomainProfile(
    domain="数字文旅产业",
    domain_aliases=("数字旅游", "文旅数字化"),
)

# 默认 mode: domain_foundation
# 完成底图后，再补 decision_context、PIR、EIE

领域初始化阶段可以暂时没有 EIE。系统此时的任务是发现和整理观察面，而不是伪造覆盖率。

模块分工

graph.pyEAR / 注意力传播

根据 typed edge 和主题查询发现跨圈层来源。

backtest.py历史回放

按 available_at 做严格的来源评价。

portfolio.py来源组合

在预算和角色约束下选择互补来源。

coverage.py覆盖审计

以 EIE 作为分母，输出机器可读缺口。

daily.py领域日报

去重、排序并保留证据链接与来源角色。

pipeline.py全链路编排

把上述模块组合成一份可复现报告。

边界原则

采集器、数据库、邮件、飞书、网页和推送都是可替换的边界适配器。领域模型、证据时间、来源评价、组合选择和覆盖审计才是核心工程。

项目范围与来源 / 版权

主产品是方法论，轮子只是边界参考。

私人情报所（Private Intelligence Observatory）以领域情报方法论、核心引擎和面向使用者的演示站为主线。仓库中的 AI News Radar 采集工程可以复用，但不属于这条主线，也不属于私人情报所的原创成果。

本项目的核心资产

  • 从领域关键词开始的 Domain Seed、Domain Map、EIE 和两层工作模式。
  • Expert Attention Reconstruction、历史截点回放、来源组合优化和 Coverage Audit。
  • 面向文旅、制造、教育、农业、医疗、能源等领域的可替换适配边界。
  • 面向从零进入领域、或已有信源但覆盖不足的使用者场景、演示入口和可视化阅读层。
