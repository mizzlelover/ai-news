# 私人情报所：来源规模与激活规则

更新时间：2026-08-31

## 先说结论

私人情报所不能只是把几条链接整理成日报。

如果一个领域只有二十几个入口，系统很容易变成“有来源的摘要工具”，却还没有形成真正的领域情报所：它既看不全这个领域由谁生产知识，也看不见标准、研究、项目交付、产品实现和一线讨论之间的差异。

因此，24 个入口只能作为领域底图的首轮骨架，不能作为一个宽领域的完整情报网络。本项目的公开数字孪生样例已经扩展为 **117 个可独立采集、历史回放和记录证据的来源入口**，并把新增来源正式接入注意力图、回放、来源组合、覆盖审计和领域日报链路。

规模不是把链接堆得越多越好，而是让一个领域的主要知识生产层、落地层和早期信号层都有人负责观察。

## 三个数字必须分开

私人情报所不把“候选雷达规模”和“每日推送数量”混成一个数字：

| 层级 | 含义 | 数字孪生公开样例 |
| --- | --- | ---: |
| Candidate Radar | 领域底图阶段可以发现、比较和持续验证的候选入口 | **117** |
| Historical Replay | 已经有首轮历史观察、可以进入来源评价的入口 | **31** |
| Daily Portfolio | 经过预算、角色互补和历史证据选择，当前进入日报组合的入口 | **24** |

117 是雷达规模，24 是当前一次组合优化的约束结果，不是项目的来源上限，也不是以后所有领域的固定默认值。没有候选雷达，日报组合会过早收窄；没有历史回放，来源数量又会变成没有质量控制的链接仓库。

## 一个合格的领域来源网络应该覆盖什么

公开数字孪生样例在首轮 22 个核心入口之外新增 95 个入口，分成七个来源层：

| 来源层 | 新增入口 | 主要任务 |
| --- | ---: | --- |
| 标准与组织 | 12 | 确认术语、标准状态、工作组、版本和互操作要求 |
| 中国政策与产业 | 10 | 追踪政策、行业标准、产业联盟、研究报告和本地化落地 |
| 采购与交付 | 3 | 发现采购意向、招投标、公共资源交易和项目交付证据 |
| 研究与学术 | 18 | 发现论文、作者、实验室、会议和前沿研究方向 |
| 平台与厂商 | 20 | 观察产品能力、版本文档、实现路径和商业化主张 |
| 开源与数据空间 | 12 | 观察参考实现、开放标准、数据空间和开发者生态 |
| 媒体与社区 | 20 | 捕捉 Newsletter、播客、行业媒体、LinkedIn 和一线讨论中的早期线索 |
| **新增合计** | **95** | **与首轮 22 个核心入口合计 117 个** |

入口按“可以独立采集、独立回放、独立记录证据的频道”计算。同一组织的标准目录、新闻页、技术文档、Newsletter、播客或 API 可以是不同入口，但不会被冒充成不同的权威机构。

## 来源不是一张总榜，而是一组分工

每个来源进入候选网络时，都要保留以下信息：

- `Source Role`：官方一手、专家解释、前沿传感器、广覆盖、社区等角色；
- `Topic / EIE`：它观察领域的哪条线，能回答哪个必需信息要素；
- `Acquisition`：RSS、Atom、公开 API、稳定 HTML、人工浏览或其他获取方式；
- `Evidence`：原始 URL、可获得时间、关系边证据和历史观察；
- `Status`：发现中、已核验候选、已有历史回放、active、watchlist 或 retired；
- `Attribution`：机构归属、作者/组织、许可证和是否存在商业立场。

官方标准和政府项目材料适合确认状态与事实；研究机构和专家组织适合解释概念与方法；厂商文档适合观察实现，但不能单独证明行业事实；媒体、Newsletter、播客、LinkedIn 和社区适合发现线索，关键判断必须回到一手材料或多源交叉证据。

## 规模化来源的激活规则

对于宽领域，项目的工程目标是先建立约 **80–150 个候选入口** 的底图，再依据领域复杂度和决策任务调整。这个范围是私人情报所的工程起始基线，不是对所有领域的机械门槛；一个很窄的专业领域可以更小，一个跨行业领域可能需要更大。

但来源进入每日组合前不能只看数量，至少要满足：

1. 有明确来源角色和领域信息要素映射；
2. 有可重复的公开获取路径，或已经明确标记为人工/登录态适配；
3. 有原始证据 URL 和可获得时间；
4. 有历史观察，能够评价提前量、准确度、误报负担和获取可靠性；
5. 与已有来源形成角色或覆盖互补，而不是重复转载；
6. 对厂商、商业媒体、社区和自媒体保留偏差与版权边界。

所以，扩充信源之后的正确动作不是把 117 个入口全部塞进日报，而是：

```text
领域关键词
→ 扩展候选来源雷达
→ Expert Attention Reconstruction
→ 来源角色与 EIE 映射
→ Point-in-time Historical Replay
→ 互补来源组合
→ Coverage Audit
→ 领域日报与持续推送
```

## 数字孪生公开样例

数字孪生样例是本项目当前的规模验证样本：

- 13 个必须持续掌握的信息要素；
- 16 个专家/机构群体节点；
- 117 个来源节点和 117 条 typed attention edges；
- 31 个来源进入历史回放评价；
- 24 个来源进入当前组合优化结果；
- 7 条带原始证据链接的 30 天发现窗口日报。

完整的来源名称、入口、角色、采集方式、状态和用途见[数字孪生扩展来源矩阵](examples/digital-twin-source-expansion-matrix.md)。机器可运行的输入 Bundle 见[`digital-twin-expanded.json`](../packages/domain-intelligence/examples/digital-twin-expanded.json)。

在仓库根目录可以直接运行这个公开样例：

```bash
uv run --project packages/domain-intelligence dib \
  packages/domain-intelligence/examples/digital-twin-expanded.json \
  --output-dir /tmp/private-intelligence-digital-twin
```

这个 Bundle 是方法论和工程的公开回放夹具，不宣称已经接通 117 个来源的实时订阅。来源适配器把运行结果和证据交给核心的契约见[来源激活运行](SOURCE_ACTIVATION_RUN.md)。真实生产还需要为每个来源配置稳定采集器、持续保存快照，并用真实运行数据替换首轮历史夹具。

## 对使用者意味着什么

使用者不需要自己先收集 117 个链接，也不需要先学会 RSS、API、爬虫或 Prompt 配置。使用者只需给出一个领域名称，私人情报所先为这个领域建立有规模的候选来源网络：

```text
我想进入的领域是：数字孪生
```

系统先回答：这个领域由什么组成、谁在生产知识、哪些标准和项目值得看、哪些来源负责确认或解释、目前哪里还没有证据。使用者已有的专家、网站、报告或项目材料，等底图建立后再直接告诉 AI 加入即可。

日报、推送和知识引擎是这张来源网络的更新与交付形式；来源网络本身必须先有足够的规模、分层和可审计的激活规则。

## 来源与版权边界

来源矩阵记录的是公开来源的入口、角色和证据指针，不复制第三方网页、论文、报告或产品文档的全文。厂商、商业媒体、Newsletter、播客和社区内容会按其真实身份标记，不会被包装成私人情报所原创内容或中立权威。

仓库中保留的 `AI News Radar`、`Radar Skill` 和旧采集脚本属于独立的边界适配参考，来源与许可证见[项目范围与来源/版权说明](PROJECT_SCOPE_AND_ATTRIBUTION.md)和[`NOTICE.md`](../NOTICE.md)。它们可以帮助采集或消费信息，但不构成这套领域规模、历史评价和来源组合方法论。
