```text

```

在当前验证机上，它的完整路径是：



## 终端用户本地网站验收

面向不会使用 AI 程序的用户，新增的本地网站入口为：

```text

→ http://127.0.0.1:8787/
```

本次验收实际观察到：

1. 本地首页能够启动并显示“给我一个领域”，没有 AI 连接时会明确阻止运行，不显示虚假的完成状态。
2. 使用安装时预配置的 OpenAI 兼容测试接口后，终端用户只输入“数字孪生”，网站真实执行领域底图校验、来源网络登记、公开入口采集、产物写出，并显示进度。
3. 运行完成后，网站跳转到带 `run` 标识的工作台；工作台通过本地 API 回读该运行的 JSON、图谱、来源、内容清单、推荐回测和日报，而不是切换到演示数据。
4. 对当前本地测试接口返回的示例入口，公开采集器按照安全边界保留了阻断结果；这证明“无法获取”会进入运行记录，而不会被包装成全文或日报。已有的真实数字孪生运行目录则已在上一节完成 117 个来源、32 份全文、3 条证据和 2 条日报故事的完整回读。
5. Chrome 浏览器桌面与 390px 移动视口验收均无页面错误或横向溢出；本地网站首页、工作台和推荐回测视图都能正常显示。

本地网站产生的测试运行保存在被 Git 忽略的 `.private-intelligence/local-runs/`，未进入公共仓库；真实运行数据同样不随代码公开发布。

## 六、为什么真实运行数据不直接放进公开仓库

公开 GitHub 仓库保存的是方法论、核心引擎、Skill、工作台、契约、测试和最小示例；本次运行的来源清单、第三方网页全文和原始响应保存在用户本机的 `.private-intelligence/` 目录中。这样既能在工作台完整回读，也不会把第三方内容快照直接作为公共仓库数据重新发布。
